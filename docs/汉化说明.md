# Pocket LED 1.5.1 汉化 + 熄屏关灯说明

产物：`PocketLED-1.5.1-zh.apk`（14,522 字节）
SHA-256：`61CCD04BAF657A708E5827A53DD2947748C2A33F826FE085D1894607D5237DE3`
版本：`versionName=1.5.1` / `versionCode=7`（上游 `v1.5` 为 `1.5` / `6`）

已在 Android 12 真机（960×720）上覆盖安装、启动、逐屏核对，并实测熄屏关灯行为。

本版 = 汉化 + **新增「熄屏时关闭指示灯」开关** + **版本号升到 1.5.1 / 7**（见下）。

## 安装前必读

- **从上游原版转过来必须先卸载**（包名同为 `com.pocketblock.led`，但签名不同，无法覆盖安装）。
  卸载会清掉原版保存的设置（亮度、配色、阈值）。
- **从本仓库的 1.5-zh 升级则直接覆盖安装**：两者用同一把自签证书，`adb install -r` 保留全部设置。
- 系统要求：Android 8.0（API 26）及以上；APK 用 **v2 签名**（targetSdk 31 必需）。
- 安装时若提示「应用未经检测 / 未知来源」，选择仍要安装即可。
- 若装完后闪退，看 `adb logcat` 是否有 `Failed to verify dex file` —— 说明系统在强校验 DEX。
  本版已按 ART 规则重排字符串表，正常情况下不会出现。

## 新增功能：熄屏时关闭指示灯

原版在屏幕息屏 / 休眠后仍会不断写 LED，灯一直亮着。本版在「控制电量指示灯」下面加了一行
开关「熄屏时关闭指示灯」：

- **开**：屏幕熄灭（含掌机休眠）后指示灯立即熄灭，屏幕重新点亮后自动恢复原来的颜色 / 亮度 / 闪烁。
- **关**：行为和原版一致（息屏也保持常亮）。
- 设置保存在 `SharedPreferences`（文件名 `led`，键 `screenOff`），重启 App / 重启设备都保留。
- 该选项只在「控制电量指示灯」开启时生效（关闭时服务本身不运行，灯归系统管）。

实现方式：`LedService.tick()` 每次刷新时先判断 `PowerManager.isInteractive()`；
若开关打开且屏幕不可交互，则改为 `Led.off()` 并只保留 1 秒后的续期调度，
不写颜色寄存器 —— 因此息屏期间不会反复点亮。

新增 / 改动的成员：

| 类 | 成员 |
|---|---|
| `Config` | `screenOff()Z`、`setScreenOff(Z)V`（`SharedPreferences` 读写） |
| `LedService` | `screenOn()Z`（`PowerManager` 查询）、`tick()` 前置判断与熄屏尾块 |
| `MainActivity` | `screenOffRow()V`（新开关行）、`onCheckedChanged(...)` 分支、`onCreate` 插入一行 |

## 版本号：1.5 → 1.5.1 / 6 → 7

`versionName` 和 `versionCode` 都在二进制 `AndroidManifest.xml`（AXML）里，不是 `resources.arsc`，
所以不需要动资源表，但也不能当纯文本改：

- `versionName="1.5"` 是 AXML **string pool** 里的字面量；长度从 3 变 5，改完必须重算
  string pool 的 offsets 数组、`stringsStart`、pool chunk size 和整个 AXML 的 header size。
- `versionCode="6"` 是 `<manifest>` 元素上的 **int 属性**（资源 ID `0x0101021b`），
  直接改那 4 字节数据即可，元素内的字符串索引不变。

`tools/bump_version.py` 只重建开头那个 pool（保留原 `utf-8/utf-16` 编码与 style 段），其余 chunk 原样后移。
**往返测试**：`1.5` → `1.5.1` → `1.5`（code `6` → `7` → `6`）后与原文件 SHA-256 完全相同，说明读写是无损的。
改完 `AndroidManifest.xml` 3180 → 3184 字节，APK 14,882 → 14,522 字节（DEX 也因新功能变化）。

## 技术做法（无 apktool / 无 Android SDK / 无 java / 无外网）

机器上没有任何 DEX 工具（apktool / jadx / smali / baksmali / d8 / javac / Android SDK 全无），
所以整套 DEX 解析、反汇编、汇编、整文件重建都是**自己用 Python 写的**（`tools/dexlib.py`、
`tools/dexbuild.py`），只有这样才能既改字符串又插新方法。

1. **DEX 文本**：UI 全部由代码构建，文本是硬编码字符串常量（357 条）。翻译 30 条后
   **必须重排字符串表**：ART 的 `DexFileVerifier` 要求 `string_ids` 严格按 UTF-16 升序
   （第一版只改文本不重排，装机即报 `Out-of-order string_ids`）。
   `tools/reindex.py` 按译文重建字符串表 → 排序 → 重写 `string_ids` 偏移 → 全量重写索引引用
   （`type_ids`、`proto_ids.shorty`、`field_ids.name`、`method_ids.name`、64 处 `const-string`），
   并清空可选的 `debug_info` / 注解（避免内部残留旧索引）。
2. **DEX 改造（新增开关）**：`tools/patch_feature.py` 在重建的 spec 上追加字符串 / 类型 / proto /
   字段 / 方法，然后做全量索引 remap（新字符串会改变所有索引，包括指令里的 `const-string`、
   方法 / 字段引用、以及类的 `static_values`），最后由 `dexbuild.build()` 生成整份 DEX：
   header → ids 段 → 各 data 段 → map_list，逐段 4 字节对齐，重算 SHA-1 与 adler32。
3. **AndroidManifest**：`label="Pocket LED"` 保持原样；只改 `versionName` / `versionCode`（见上一节）。
4. **打包**：手写 ZIP（`resources.arsc` 保持 stored 且 4 字节对齐），去掉原 v1 签名文件。
5. **签名**：APK Signature Scheme **v2**。自签名 RSA-2048 证书，Python 纯实现 PKCS#1 v1.5 / SHA-256
   签名，手工组装 APK Signing Block（`0x7109871a`），1MB 分块 SHA-256 内容摘要（0xa5/0x5a）。
   结构细节（对照真机已装 APK 的签名块逐字节核过）：`value = lp(lp(signer))`，
   且 **digests / signatures 的每条记录本身也要套一层长度前缀**：
   `digests = lp(lp(u32 算法 ID + lp(digest)))`、`signatures = lp(lp(u32 + lp(sig)))`，
   pair 长度字段 = `4 + value_len`。

### 自写 DEX 工具踩过的坑（留档）

- **22b 格式**（`add-int/lit8` 等）真实布局是 `unit0 = op|A<<8`、`unit1 = B | lit8<<8`；
  按「A 只有 4 位」解会把自增 / 自减循环写成死循环（表现为界面全黑、ANR）。
  真机上 `/apex/com.android.art/bin/dexdump -d` 是权威仲裁，靠它定案的。
- 重建时**必须写回 `static_values`**（`Led.DIR`、闪烁间隔等静态常量），否则类初始化失败
  → `ClassNotFoundException` / 黑屏；同时 class_def 的第 8 个字段和 map 的 0x2005 条目都要填。
- `parse_encoded_value` 的 size 位段是 `(b>>5)+1`，掩码后再右移会恒为 0 → 数组被截断。
- `map_list` 与每个 `type_list` 条目都要 4 字节对齐，否则 ART 报
  `Offset(…) should be aligned by 4 for map` / `Non-zero padding … before section`。
- AXML 只有 8 字节文件头 + 若干 chunk，**改 string pool 长度时必须同步改文件头的 total size**，
  并保留原 chunk 顺序；`bump_version.py` 第一版忘了把文件头拼回去，写出的是 8 字节偏移的文件。
- 校验流程：`encode_code` 与原文逐字节比对（83/83 方法零差异）→ `roundtrip.py` 语义往返 →
  `validate.py` 寄存器 / 索引 / 分支越界检查 → 真机 `dex2oat --dex-file=t.dex` 快检 → 装机。

## 构建校验（tools/ 目录）

- `reindex.py`：字符串重排 + 全量索引重写（汉化用），自带升序自检
- `dexlib.py` / `dexbuild.py`：DEX 解析、反汇编、汇编、整文件重建
- `patch_feature.py`：在汉化 DEX 上追加「熄屏时关闭指示灯」（含字节码插入与索引 remap）
- `bump_version.py`：重写 AXML 的 `versionName` / `versionCode`，往返无损
- `cmpenc.py` / `cmpbytes.py`：编码结果与原文逐字节 / 整文件比对；`roundtrip.py`：语义往返
- `validate.py`：寄存器与索引边界检查；`dump2.py`：带操作数的反汇编
- `verify_dex.py`：header 校验和、SHA-1、字符串可读性
- `verify_apk.py`：zip CRC、Signing Block 结构（按 per-record LP 解析）、内容摘要重算、
  RSA 验签、证书与公钥一致性、`resources.arsc` 对齐；输出 `ALL CHECKS PASSED`
- `walk_block.py`：签名块 pair 遍历一致性；`e2e_check.py`：从成品 APK 解包复核文本

重新构建顺序：`reindex.py`（汉化）→ `patch_feature.py`（新功能）→ `bump_version.py`（改版本号）
→ `build_apk.py` → `verify_apk.py`

> 这些脚本的输入输出路径按作者本机目录写死（Windows 绝对路径），换机器要改根路径。
