# 汉化说明（技术细节）

这份文档记录 `PocketLED-1.5-zh.apk` 是怎么来的，方便以后原版更新时重做，也方便别人复核。

## 起点

- 原始 APK：官方 v1.5 发布包 `PocketLED-1.5.apk`（可用 `adb shell dumpsys package com.pocketblock.led` 核对 versionName 1.5 / versionCode 6）
- 汉化产物：`PocketLED-1.5-zh.apk`，14,882 字节
- SHA-256：`F86DACF1B0770BE92B0D82149E56E351F758A39DD5914FD9734CADC31AAF459E`

## 麻烦在哪

原版**没有 `strings.xml`**：整套 UI 是 `MainActivity` 里用代码拼出来的（`text("...")`、`setText("...")`），文案以字符串字面量的形式硬编码在 `classes.dex` 的 `string_data` 段里。资源目录 `res/` 只有图标，所以没法用「加一个 `values-zh/strings.xml`」的常规做法汉化。

只能改 DEX。而 DEX 的 `string_ids` 表要求**严格按 UTF-16 码点升序排列**，ART 的 `DexFileVerifier` 会检查。中文译文的码点基本都在 ASCII 之后，改完文本一排序，后面的偏移全变——只改文本不重排，装机直接报：

```
Out-of-order string_ids: '% 及以下' then ' %)'
```

## 做法

1. **重排字符串表**：按译文重建 `string_data`，按 UTF-16 排序，重写 `string_ids` 的偏移表，然后把所有引用旧索引的地方全量重写——`type_ids`、`proto_ids.shorty`、`field_ids.name`、`method_ids.name`，以及 64 处 `const-string` 指令。同时把可选的 `debug_info` / 注解字段置 0，避免里面残留的旧索引变脏。
2. **保持其余段不动**：文件长度仍是 20,148 字节，各段偏移不变，最后重算 header 的 SHA-1 与 adler32。
3. **AndroidManifest 保持原样**：`label="Pocket LED"` 不翻译，因此与原文件逐字节一致（早先一版曾把标签改成「口袋 LED」并重建 UTF-16 池，后来回退了）。
4. **重新打包**：手写 ZIP，`resources.arsc` 保持 stored 且 4 字节对齐，去掉原 v1 签名文件。
5. **重新签名**：APK Signature Scheme **v2**。自签名 RSA-2048 证书，PKCS#1 v1.5 / SHA-256，手工组装 APK Signing Block（ID `0x7109871a`），1 MB 分块做内容摘要（chunk `0xa5` / `0x5a`）。

   签名块的结构细节（对照真机上已安装 APK 的签名块逐字节核过）：

   ```
   value = lp(lp(signer))
   digests    = lp(lp(u32 算法 ID + lp(digest)))
   signatures = lp(lp(u32 算法 ID + lp(sig)))
   pair 长度字段 = 4 + value_len
   ```

   即每条 digests / signatures 记录本身还要套一层长度前缀——这一点容易写错，写错了 Android 12 会直接判「签名无效」。

## 换了签名意味着什么

包名不变，证书变了，所以：

- **不能覆盖安装**，必须先卸载原版；
- 卸载原版会连带清掉它 `SharedPreferences` 里的设置（亮度、配色、阈值）；
- 装了汉化版之后要回原版，同样得先卸载。

## 校验清单

成品 APK 上复核过这些（全部通过）：

- ZIP 内每个条目的 CRC
- `classes.dex` header 校验和、SHA-1、357 条字符串全部可读
- Signing Block 结构（按 per-record 长度前缀解析）、内容摘要重算
- RSA 验签、证书与公钥一致性
- `resources.arsc` 的 4 字节对齐
- 解包回读，逐条比对译文

真机上（Pocket Block / Android 12）安装、启动、逐档切换、通知、开机自启都实际点过一遍。

## 以后原版更新怎么跟进

1. 反编译新 APK，导出 `string_data` 里的 357 条字符串；
2. 对比旧版，找出新增/改动的文案，翻译；
3. 重排字符串表、重写全部索引引用（这一步没有工具就必须手算，建议直接找现成脚本改）；
4. 重打包 + v2 签名；
5. 按上面的校验清单过一遍，再真机装机确认。
